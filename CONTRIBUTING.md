# Contributing

This is an experimental public project. Original code is
0BSD licensed. Preserve the standalone selector's single-source-file,
standard-library-only design and Python 3.11 compatibility.

That constraint applies to the original selector. The optional `futures_ts`
package is isolated under `src/`, uses Python 3.12 and declared dependencies,
and must not introduce those dependencies into `contract_coverage.py`.
The separate `product_coverage` package follows the same isolation rule; its
generic methods must not depend on a vendor root list or import a vendor SDK.
Keep file mappings synthetic and document the exact policy class for minimum
claims. New optimizers need independent small exhaustive comparisons.

Install development dependencies with `python -m pip install -c
requirements/validation.txt '.[databento,test,release]'`. The base installation
must work without a vendor SDK. Presentation escaping must not alter canonical
JSON/Parquet identities; generic policies use report v2 and checksummed JSON.
Reject malformed policies in both file imports and the in-memory API.

For pipeline changes, run `python3.12 -m pytest tests/ -q` as well as the embedded
selector suite below. DBN fixtures must be generated by
`tests/generate_fixtures.py` in temporary or ignored directories. The test harness
blocks network connections. Run `python3.12 -m tests.benchmark_synthetic --work
out/memory-check --scale 5` for a synthetic memory check on macOS/Linux; record
its dimensions and peak RSS without claiming a full real-data certification.

Run the embedded suite from the repository root:

```sh
python3 contract_coverage.py --self-test
```

For a CLI change, also run the sample through JSON, CSV, and the readable summary:

```sh
mkdir -p output
python3 contract_coverage.py --input examples/input.json \
  --output output/report.json --csv output/recommendations.csv --summary
```

Add meaningful regression cases to `CoverageTests` for changed decisions,
historical ranks, missingness, accounting, or validation. When changing the
output schema or policy defaults, update the input/policy reference and explain
the compatibility impact. Keep ordering deterministic and JSON values finite.

Use only synthetic fixtures. Store real inputs in ignored `data/` and outputs
in ignored `output/`. Review `git diff --cached` and the staged file list before
pushing; filenames and ignore rules alone do not establish that data is safe to
share. Do not commit vendor extracts, credentials, or local machine paths.
Do not attach licensed inputs or actual activity reports to public issues.
Follow SECURITY.md for vulnerabilities. New changes must not weaken the socket
block or silently bypass failing security checks.

Release validation is documented in docs/PUBLIC_RELEASE.md. Local commits do
not authorize pushing, merging, publishing packages or changing visibility.

When intentionally changing sample recommendations, regenerate the expected
CSV from `examples/input.json` and update `examples/summary.txt` together. These
files are illustrative fixtures, not evidence of real-market performance.
